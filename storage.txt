Where to check the rotation settings

/etc/logrotate.conf holds the defaults.
/etc/logrotate.d/ has one file per application. grep -rn "pan\|remotelogs" /etc/logrotate.d/ shows which rule covers your folders, if any. Most likely pan-rsyslog still points at the old /var/log/remotelogs.
/var/lib/logrotate/status shows when each file was last rotated.
systemctl list-timers logrotate.timer shows when logrotate runs (once a day on Ubuntu).

Why the script doesn’t help: it never touches /var/log/pan. It empties syslog, auth.log, kern.log and messages, empties the old remotelogs folder, deletes files that were already rotated, and runs only once a week. Live files that nothing rotates just keep growing.
Second: the fix

Free up space now (pick one)

Grow the root disk, which loses nothing. In EC2 → Volumes, modify the root volume’s size, then on the box run sudo growpart /dev/nvme0n1 1 and sudo resize2fs /dev/nvme0n1p1. Check the device names with lsblk first.
Or empty the traffic files, once Sentinel has caught up. Check that the last line of the file (sudo tail -n1 <file>) and PaloAltoTraffic_CL | summarize max(TimeGenerated) are only minutes apart. Then run sudo truncate -s 0 /var/log/pan/traffic/user/*.log. Use truncate, not rm: deleting a file that rsyslog has open doesn’t free the space.

The permanent fix: replace /etc/logrotate.d/pan-rsyslog with:

/var/log/pan/*/*/*.log {
    daily
    rotate 3
    maxage 3
    maxsize 2G
    compress
    missingok
    notifempty
    sharedscripts
    postrotate
        /usr/lib/rsyslog/rsyslog-rotate
    endscript
}
“Every 3 days”: logrotate only rotates daily, weekly or monthly. daily plus rotate 3 keeps the live file and the last 3 days compressed. That also covers Microsoft’s advice to keep text-log files at least two days so AMA can finish reading them.
maxsize 2G rotates a file early once it passes 2 GB, but only when logrotate runs, so make it run hourly with sudo systemctl edit logrotate.timer and add:
  [Timer]
  OnCalendar=
  OnCalendar=hourly

Your daily rules still rotate once a day; the hourly run only adds the size check.

Dry run first: sudo logrotate -d /etc/logrotate.d/pan-rsyslog shows what it would do without changing anything.
Check the sizing after a day with sudo du -sh /var/log/pan/*/user. Three compressed days plus one live day should take at most about half the disk. If they don’t fit, grow the disk or lower rotate.

After that, retire the cleanup script.

Third: monitoring

AMA covers most of this. Turn each query below into an Azure Monitor log search alert with an action group (email or Teams). If the SOC should get incidents instead, use a Sentinel scheduled rule.

1. Disk, CPU and memory. Create a DCR for the collectors: Monitor → Data Collection Rules → Create → Linux → data source Performance Counters → Basic. The data lands in the Perf table.

kql
Perf
| where TimeGenerated > ago(15m)
| where ObjectName == "Logical Disk" and CounterName == "% Used Space" and InstanceName == "/"
| summarize UsedPct = max(CounterValue) by Computer
| where UsedPct > 80

Once data arrives, check the exact names with Perf | distinct ObjectName, CounterName, InstanceName.

2. A collector or its agent is down. AMA sends a heartbeat every minute.

kql
Heartbeat
| where TimeGenerated > ago(1d)
| summarize Last = max(TimeGenerated) by Computer
| where Computer startswith "ip-10-29-1-" and Last < ago(10m)

3. A table or a firewall went silent

kql
union isfuzzy=true PaloAltoThreat_CL, PaloAltoTraffic_CL, PaloAltoUrlFiltering_CL
| where TimeGenerated > ago(7d)
| summarize Last = max(TimeGenerated) by Table = Type, Sender = Computer
| where Last < ago(1h)

For the Syslog table, run the same idea grouped by Facility, HostName. Quiet facilities like auth need a longer window, or they’ll alert constantly.





It keeps 7 days.
delaycompress leaves yesterday’s file uncompressed. With traffic logs, that’s a big file.
Nothing limits file size during the day.

Here’s your file with four changes. I tested it with logrotate in my sandbox.

/var/log/pan/*/*/*.log {
    daily
    maxsize 1G
    rotate 3
    compress
    missingok
    notifempty
    dateext
    dateformat -%Y%m%d-%H%M%S
    create 0640 syslog adm
    sharedscripts
    postrotate
        systemctl kill -s HUP rsyslog.service >/dev/null 2>&1 || true
    endscript
}
rotate 7 → rotate 3: keeps 3 old files instead of 7.
delaycompress removed: rotated files get compressed right away.
maxsize 1G added: rotates a file early once it passes 1 GB.
dateformat now includes the time. With the date-only format, a second size-based rotation on the same day fails (“destination already exists, skipping rotation”), and the file keeps growing. My test reproduced that.

On busy days, size-based rotations mean the 3 kept files can cover less than 3 days. That’s the trade-off that keeps the disk safe, and the data itself is already in Sentinel.

Backup: copy it, don’t rename it in place. Keep the copy outside /etc/logrotate.d. logrotate reads every file in that folder. The version I tested skips .bak names, but older versions may not, and then the copy clashes with the real file.

Step by step on the collector

See what’s there:
bash
   df -h /
   sudo du -sh /var/log/pan/*/user
   ls -lh /var/log/pan/traffic/user/
Free space now. The new rule won’t clean up files rotated under the old date-only naming; my test confirmed it leaves them. So remove the old ones by age, then compress the uncompressed one:
bash
   sudo find /var/log/pan -type f -name "*.log-*" -mtime +2 -print -delete
   sudo find /var/log/pan -type f -name "*.log-*" ! -name "*.gz" -print -exec gzip {} \;

If gzip fails for lack of space, delete that uncompressed file instead. Its contents are already in Sentinel.

Back up the current rule:

   sudo cp /etc/logrotate.d/pan-rsyslog /root/pan-rsyslog.$(date +%F).bak
Replace the content with the config above:

   sudo nano /etc/logrotate.d/pan-rsyslog
Dry run. This changes nothing and shows only errors and the Palo Alto lines:

Rotate once now to shrink today’s big files:

Make logrotate run hourly, so maxsize gets checked during the day:

   OnCalendar=hourly
