The service failed, or the timer shows no NEXT time. Step 5 fixes the timer.

4. Install the new rule
bash
sudo cp /etc/logrotate.d/pan-rsyslog /root/pan-rsyslog.$(date +%F).bak
sudo tee /etc/logrotate.d/pan-rsyslog > /dev/null <<'EOF'
/var/log/pan/*/*/*.log {
    daily
    maxsize 5G
    rotate 30
    maxage 3
    compress
    missingok
    notifempty
    dateext
    dateformat -%Y%m%d-%H%M%S
    create 0640 syslog adm
    sharedscripts
    postrotate
        systemctl kill -s HUP rsyslog.service >/dev/null 2>&1 || true
    endscript
}
EOF
sudo chown root:root /etc/logrotate.d/pan-rsyslog
sudo chmod 644 /etc/logrotate.d/pan-rsyslog
sudo find /var/log/pan -type f \( -name '*.log-????????' -o -name '*.log-????????.gz' \) -print -delete
Backup: copy it to /root; don’t rename it in place. logrotate reads almost every file in that folder, so a renamed copy becomes a second rule for the same logs.
What the rule does:
It rotates daily, or as soon as a file passes 5 GB (checked hourly, step 5).
It keeps compressed copies for 3 days. rotate 30 is only an upper limit.
The time in the file name lets a file rotate more than once a day.
The find line: it deletes old files rotated under the date-only names, if there are any. They’re already in Sentinel, and the new rule won’t recognise that name format.
5. Run logrotate hourly
bash
sudo mkdir -p /etc/systemd/system/logrotate.timer.d
sudo tee /etc/systemd/system/logrotate.timer.d/hourly.conf > /dev/null <<'EOF'
[Timer]
OnCalendar=
OnCalendar=hourly
AccuracySec=1m
EOF
sudo systemctl daemon-reload
sudo systemctl enable logrotate.timer
sudo systemctl restart logrotate.timer
systemctl list-timers logrotate.timer --no-pager     # NEXT = top of the next hour

This doesn’t affect the other logrotate rules. They still rotate only when their own daily or weekly condition is met.
