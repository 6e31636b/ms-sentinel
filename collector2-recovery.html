Collector 2 recovery plan

Collector 2 (ip-10-29-1-5, 10.29.1.5) went down with a full disk, and its Azure Arc connection has most likely expired, which is the certificate error in the portal. Work through the steps in order: keep it away from live traffic, reconnect it, copy collector 1's configuration, add AMA and the DCRs back, test, and only then return it to the NLB.

Keep it out of the NLB

If 10.29.1.5 is still registered in the syslog target group, it turns healthy as soon as rsyslog listens on port 514. The NLB then sends it logs that can't reach Sentinel yet.

In AWS, go to EC2 → Target groups → the syslog target group → Targets, select 10.29.1.5 and deregister it. Step 6 registers it again.

Reconnect to Azure Arc

Do this if step 1 showed Expired or a certificate error. A machine that stays disconnected for 45 days can expire, and then it can't be managed through Arc until it is disconnected and reconnected (Microsoft Learn).

bash
# Keep: Resource Name, Resource Group Name, Subscription ID, Tenant ID, Location
sudo azcmagent show > ~/arc-before.txt
sudo apt-get update && sudo apt-get install --only-upgrade azcmagent ca-certificates
sudo systemctl stop extd
# Note what's listed; AMA and the rest come back from Azure in step 4
sudo azcmagent extension list
sudo azcmagent extension remove --all
# Deletes the old Arc resource; sign in with the device code it shows
sudo azcmagent disconnect
sudo azcmagent connect --use-device-code --resource-name ip-10-29-1-5 \
  --subscription-id "<Subscription ID>" --resource-group "<Resource Group Name>" \
  --tenant-id "<Tenant ID>" --location "<Location>"
# Expect: Connected, and a newer agent version
sudo azcmagent show | grep -iE "agent status|agent version"
  • Take the values for connect from ~/arc-before.txt, so the machine comes back with the same name in the same resource group and region. Sign in with an account allowed to onboard Arc machines there.
  • Remove the extensions before disconnecting: extensions left installed aren't recognized after reconnecting (Microsoft Learn). The removal works while the machine is disconnected, as long as the extension manager (extd) is stopped (Microsoft Learn).
  • If apt can't reach the Microsoft package repository, reinstall the agent with the Linux install script from the Azure Arc onboarding page in the portal.

If azcmagent disconnect fails

Delete the machine in the portal under Azure Arc → Machines, then reset only the local agent (Microsoft Learn) and continue with connect:

bash
sudo azcmagent disconnect --force-local-only
3

Copy collector 1's configuration

Copy only the files you manage yourselves. AMA writes its own 10-azuremonitoragent-omfwd.conf, so that one stays as it is.

On collector 1

bash
cd / && sudo tar czf /tmp/collector-config.tgz \
  etc/rsyslog.conf \
  etc/rsyslog.d/01-filter-checkpoint-log.conf \
  etc/rsyslog.d/05-paloalto.conf \
  etc/logrotate.d/pan-rsyslog \
  etc/systemd/system/logrotate.timer.d \
  etc/systemd/system/logrotate.service.d
sudo chmod 644 /tmp/collector-config.tgz
sha256sum /tmp/collector-config.tgz
tar tzf /tmp/collector-config.tgz

Add etc/rsyslog.d/00-impstats.conf to the list if you created it. Copy the file to /tmp on collector 2 the way you usually move files (WinSCP or scp).

On collector 2

bash
# Must print the same checksum as on collector 1
sha256sum /tmp/collector-config.tgz
# Backup of the current configuration
sudo tar czf /root/config-before-sync-$(date +%F).tgz /etc/rsyslog.conf /etc/rsyslog.d /etc/logrotate.d /etc/systemd/system
sudo systemctl stop syslog.socket rsyslog
# Move data from before the crash out of AMA's way
sudo mv /var/log/pan /root/pan-old-$(date +%F)
sudo mkdir -p /root/spool-old && sudo find /var/spool/rsyslog -name 'omfwd-azuremonitoragent*' -exec mv -t /root/spool-old {} +
sudo tar xzf /tmp/collector-config.tgz -C /
ls /etc/rsyslog.d/

The two mv lines move months-old Palo Alto files and queued messages from before the crash out of the way, so AMA doesn't ingest them once it's back. Stopping syslog.socket as well keeps journald from restarting rsyslog while that happens.

Remove what collector 1 doesn't have, then validate

Compare ls /etc/rsyslog.d/ on both collectors and move to /root every file that only collector 2 has. Likely candidates are 30-paloalto.conf (the old rule that caused the duplicates), 95-omsagent.conf and security-config-omsagent.conf.

bash
# Repeat for each file collector 1 doesn't have
sudo mv /etc/rsyslog.d/30-paloalto.conf /root/
sudo rsyslogd -N1 2>&1 | grep -iE "error|warn" || echo "config OK"
sudo systemctl daemon-reload && sudo systemctl start rsyslog && sudo systemctl restart logrotate.timer
# Expect no output
sudo logrotate -d /etc/logrotate.conf 2>&1 | grep -iE "error|ignoring"
# Expect: TimeoutStartUSec=infinity
systemctl show logrotate.service -p TimeoutStartUSec

Nothing in this step is deleted. Remove /root/pan-old-* and /root/spool-old yourself once collector 2 has run cleanly for a day.

4

Add AMA and the DCRs back

  • In the portal, open Azure Arc → Machines → ip-10-29-1-5 → Extensions → Add → Azure Monitor Agent for Linux. Add back anything else that the extension list in step 2 showed.
  • For each DCR collector 1 uses (CEF, Syslog, Palo Alto threat and traffic, and any others), open the DCR → Resources → Add → ip-10-29-1-5.

To list collector 1's DCRs in Cloud Shell:

bash
az monitor data-collection rule association list \
  --resource "<collector 1 Arc resource ID>" \
  --query "[].dataCollectionRuleId" -o tsv

Test before it takes traffic

On collector 2:

bash
systemctl is-active azuremonitoragent rsyslog
# Same count as on collector 1
sudo ls /etc/opt/microsoft/azuremonitoragent/config-cache/configchunks/ | wc -l
logger -p user.info "collector2 path test"

In Sentinel, after 5 to 10 minutes, both queries should return a row:

kql
Heartbeat
| where Computer startswith "ip-10-29-1-5"
| summarize Last = max(TimeGenerated)
kql
Syslog
| where TimeGenerated > ago(30m) and SyslogMessage has "collector2 path test"
6

Return it to the NLB

Register 10.29.1.5 in the target group again and wait until it shows Healthy. Then confirm both collectors are sending data:

kql
union PaloAltoThreat_CL, PaloAltoTraffic_CL, CommonSecurityLog, Syslog
| where TimeGenerated > ago(30m)
| summarize Rows = count() by Collector = tostring(split(_ResourceId, "/")[-1]), Type

Each collector should appear with rows for the Palo Alto tables and for Syslog or CommonSecurityLog.
