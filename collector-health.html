How the collector works

Every event enters on port 514 and leaves through AMA by one of two paths, and each check below looks at one stage of them. Palo Alto threat, URL and traffic logs are written to files that AMA reads; everything else is forwarded straight to AMA.

Part 1 · Daily

Daily CLI check

Paste this block on each collector; every numbered result should match the Good column below. Use it daily, and any time you don't know the collector's state.

bash
# 1 Disk and inodes (the root disk holds /var/log)
df -h / ; df -i /
# 2 Services
systemctl is-active rsyslog azuremonitoragent himdsd
systemctl --failed --no-pager --plain | head
# 3 Arc connection (AMA needs it to send)
sudo azcmagent show | grep -iE "agent status|last heartbeat"
# 4 Listening ports
sudo ss -lntup | grep -E ':(514|28330) '
# 5 Palo Alto files: written in the last 5 min / silent over 1 h / over 6 GB / size per type
sudo find /var/log/pan -name '*.log' -mmin -5 | wc -l
sudo find /var/log/pan -name '*.log' -mmin +60
sudo find /var/log/pan -name '*.log' -size +6G
sudo sh -c 'du -sh /var/log/pan/*/user'
# 6 Rotation
systemctl show logrotate.service -p Result -p ExecMainExitTimestamp
systemctl list-timers logrotate.timer --no-pager | head -2
# 7 rsyslog: warnings in the last 24 h, queue spilled to disk, config valid
sudo journalctl -u rsyslog --since -24h -p warning --no-pager | tail -5
sudo du -sh /var/spool/rsyslog
sudo rsyslogd -N1 2>&1 | grep -iE "error|warn" || echo "config OK"
# 8 AMA: latest errors, upload cache size
sudo tail -n 5 /var/opt/microsoft/azuremonitoragent/log/mdsd.err
sudo du -sh /var/opt/microsoft/azuremonitoragent/events
# 9 Load, memory, clock
uptime ; free -h | head -2 ; timedatectl | grep -i synchronized

End-to-end check in Sentinel

The CLI check shows the collector is healthy; these two queries show the data is actually arriving. Run them in the workspace's Logs after the CLI check.

The first lists every source that sent in the last 24 hours, longest silence first. Anything silent for over 60 minutes needs a look. A whole table silent points at the collector or that table's DCR; one firewall silent points at that firewall.

kql
// Every source seen in the last 24 h, longest-silent first
let window = 24h;
union isfuzzy=true
    (Heartbeat | where TimeGenerated > ago(window)
        | summarize Last = max(TimeGenerated) by Source = Computer | extend Table = "Heartbeat"),
    (Syslog | where TimeGenerated > ago(window)
        | summarize Last = max(TimeGenerated) by Source = strcat(HostName, " / ", Facility) | extend Table = "Syslog"),
    (CommonSecurityLog | where TimeGenerated > ago(window)
        | summarize Last = max(TimeGenerated) by Source = strcat(DeviceVendor, " ", DeviceProduct, " / ", Computer) | extend Table = "CommonSecurityLog"),
    (PaloAltoThreat_CL | where TimeGenerated > ago(window)
        | summarize Last = max(TimeGenerated) by Source = Computer | extend Table = "PaloAltoThreat_CL"),
    (PaloAltoUrlFiltering_CL | where TimeGenerated > ago(window)
        | summarize Last = max(TimeGenerated) by Source = Computer | extend Table = "PaloAltoUrlFiltering_CL"),
    (PaloAltoTraffic_CL | where TimeGenerated > ago(window)
        | summarize Last = max(TimeGenerated) by Source = Computer | extend Table = "PaloAltoTraffic_CL")
| extend MinutesSilent = datetime_diff('minute', now(), Last)
| project Table, Source, Last, MinutesSilent
| order by MinutesSilent desc

The second charts ingested volume per table per hour over 3 days. A dip or a flat line shows partial loss that the first query can miss, because a source can still send a little while most of its data is lost.

kql
// Ingested MB per table per hour, last 3 days
Usage
| where TimeGenerated > ago(3d)
| where DataType in ("Syslog", "CommonSecurityLog", "PaloAltoThreat_CL", "PaloAltoUrlFiltering_CL", "PaloAltoTraffic_CL")
| summarize MB = sum(Quantity) by DataType, bin(TimeGenerated, 1h)
| render timechart

If a table is on the data lake tier, queries on it are billed per GB scanned. A 24-hour scan of the traffic table reads a full day of it, 50 GB or more, so drop that line if the cost matters.

Emergency: disk over 90% or full

A full disk stops rsyslog from writing the Palo Alto files and stops AMA from buffering, so logs are lost until space comes back. Free space first and find the cause second.

1 Free space now

Empty the biggest live traffic files, largest first:

bash
sudo sh -c 'ls -lhS /var/log/pan/traffic/user/ | head'
sudo truncate -s 0 '/var/log/pan/traffic/user/<firewall FQDN>.log'
# or every traffic file at once:
sudo sh -c 'truncate -s 0 /var/log/pan/traffic/user/*.log'
df -h /

Use truncate, never rm. rsyslog and AMA keep the files open, so rm frees nothing until they restart, while truncate frees the space at once and both carry on writing and reading the same file. Lines AMA hadn't sent yet are lost, so empty traffic files before threat files.

2 Find what filled it

bash
sudo du -xah / 2>/dev/null | sort -h | tail -25
sudo lsof -nP +L1 2>/dev/null | awk 'NR==1 || $7 > 1e9'

The first command lists the biggest folders and files on the root disk. The second lists deleted files that a process still holds open; that space only comes back when the process restarts, usually sudo systemctl restart rsyslog.

3 Check that logging recovered

Rerun checks 2, 5 and 7 of the daily check. The live files should be growing again within a minute; if not, restart rsyslog, then azuremonitoragent.

4 Fix the cause

In October it was rotation (check 6). Start a run and watch it until it shows inactive (dead) with status=0/SUCCESS:

bash
sudo systemctl start --no-block logrotate.service
systemctl status logrotate.service --no-pager -n 5

Files ending in .backup under /var/log/pan are half-compressed leftovers of a rotation that was killed; delete them.

Part 2 · Monitoring

What breaks and how we'll know

The goal is an alert within about 15 minutes for every failure that has hit this setup or could, built on data AMA already sends or can send with three changes. Signals to collect

Everything the alerts need either already reaches the workspace or arrives through one new DCR, so nothing new has to be installed on the collectors. Alert rules can't read tables on the data lake tier: when a table moves there, "all real-time analytics and hunting queries stop working" (Microsoft Learn). If the Palo Alto tables stay on that tier, the collector-health script's per-file ages are what tells you a firewall went quiet.

Collector and DCR changes

The plan needs one small file on each collector and one new DCR, and it leaves the existing DCRs and the Palo Alto rules untouched.

1. rsyslog statistics on each collector

This turns on rsyslog's impstats module. Restart at a quiet moment, because UDP senders lose the second or two a restart takes.

bash
sudo tee /etc/rsyslog.d/00-impstats.conf > /dev/null <<'EOF'
# rsyslog health counters every 60 s as JSON (facility syslog, tag rsyslogd-pstats).
# AMA sends them to the Syslog table through the collector-health DCR.
module(load="impstats" interval="60" resetCounters="on" format="json")
EOF
sudo rsyslogd -N1 2>&1 | grep -iE "error|warn" || echo "config OK"
sudo systemctl restart rsyslog
sleep 70; sudo grep rsyslogd-pstats /var/log/syslog | tail -3

Every minute rsyslog then logs about 20 lines like { "name": "main Q", "origin": "core.queue", "size": 16, "full": 0, "discarded.full": 0, ... }, one per queue, input and output. Tested on rsyslog 8.2312. resetCounters makes each line a count for that minute, which keeps the alert queries simple.

2. New DCR, collector-health

Name it alp-dcr-sentinel-prod-01-linux-collector-health, kind Linux, with the same workspace destination as the others, and associate it with every collector. It holds performance counters plus two syslog facilities that no existing DCR collects, so nothing is ingested twice.

json
"dataSources": {
  "performanceCounters": [
    { "name": "collectorPerf", "streams": ["Microsoft-Perf"], "samplingFrequencyInSeconds": 60,
      "counterSpecifiers": [
        "Logical Disk(*)\\% Used Space",
        "Logical Disk(*)\\% Used Inodes",
        "Logical Disk(*)\\Free Megabytes",
        "Memory(*)\\% Used Memory",
        "Memory(*)\\Available MBytes Memory",
        "Processor(*)\\% Processor Time",
        "Network(*)\\Total Bytes Received" ] }
  ],
  "syslog": [
    { "name": "rsyslogHealth", "streams": ["Microsoft-Syslog"], "facilityNames": ["syslog"],
      "logLevels": ["Info", "Notice", "Warning", "Error", "Critical", "Alert", "Emergency"] },
    { "name": "serviceFailures", "streams": ["Microsoft-Syslog"], "facilityNames": ["daemon"],
      "logLevels": ["Warning", "Error", "Critical", "Alert", "Emergency"] }
  ]
},
"dataFlows": [
  { "streams": ["Microsoft-Perf"], "destinations": ["la-sentinel"] },
  { "streams": ["Microsoft-Syslog"], "destinations": ["la-sentinel"],
    "transformKql": "source | where ProcessName in ('rsyslogd', 'rsyslogd-pstats', 'systemd', 'collector-health')" }
]

The transformation keeps only the collectors' own messages, so a remote device that happens to log with facility daemon or syslog isn't ingested.

3. Error logging on every DCR

On each DCR (CEF, syslog, Palo Alto threat, traffic and URL, collector-health), open Diagnostic settings, select Log Errors and send it to the workspace. Failed rows then land in the DCRLogErrors table with the reason.

4. Optional: collector-health script

A systemd timer runs a short script every 5 minutes. It logs one JSON line per Palo Alto file with the type, firewall, size and minutes since the last write, plus the last logrotate result and the AMA cache and rsyslog spool sizes. It sends them with logger -p syslog.info -t collector-health, so the same DCR picks them up. This gives per-firewall freshness whatever tier the Palo Alto tables are on.

Alert rules

Create each rule below as an Azure Monitor log search alert on the workspace, with the condition "number of results greater than 0". Point every rule at one action group (email plus the team's Teams channel). Each query returns rows only when something is wrong, and the rows say what. Log search alerts read at most two days back (Microsoft Learn), which is why the volume rule compares with yesterday rather than last week.

Disk filling Sev 2 Sev 1

Create it twice: 80% at severity 2 and 90% at severity 1.

kql
Perf
| where TimeGenerated > ago(15m)
| where ObjectName == "Logical Disk" and CounterName == "% Used Space" and InstanceName == "/"
| summarize UsedPct = round(max(CounterValue), 1) by Computer
| where UsedPct >= 80

Service failed Sev 2

Any systemd unit failure on a collector, such as the logrotate timeout, an rsyslog crash or an AMA crash.

kql
Syslog
| where TimeGenerated > ago(15m) and ProcessName == "systemd"
| where SyslogMessage contains "Failed with result" or SyslogMessage contains "Failed to start"
| project TimeGenerated, HostName, SyslogMessage

Collector silent Sev 1

No Heartbeat for 10 minutes, which means the VM, AMA or the Arc connection is down.

kql
let collectors = datatable(Computer: string) ["ip-10-29-1-71"];
collectors
| join kind=leftouter (
    Heartbeat | where TimeGenerated > ago(30m) | summarize Last = max(TimeGenerated) by Computer
  ) on Computer
| where isnull(Last) or Last < ago(10m)
| project Computer, Last

rsyslog not reporting Sev 1

AMA is alive but rsyslog's statistics stopped, so rsyslog is down or can't hand data to AMA.

kql
let collectors = datatable(Computer: string) ["ip-10-29-1-71"];
let alive = Heartbeat | where TimeGenerated > ago(10m) | distinct Computer;
let reporting = Syslog | where TimeGenerated > ago(10m) and ProcessName == "rsyslogd-pstats"
    | project Computer = HostName | distinct Computer;
collectors
| where Computer in (alive) and Computer !in (reporting)

rsyslog queue trouble Sev 2

A queue was full or dropped messages, holds over 20,000 messages (the AMA queue holds 25,000 in memory), or spilled to disk.

kql
Syslog
| where TimeGenerated > ago(15m) and ProcessName == "rsyslogd-pstats"
| extend s = parse_json(SyslogMessage)
| where tostring(s.origin) == "core.queue"
| summarize MaxSize = max(toint(s.size)), Full = sum(toint(s.full)),
            Discarded = sum(toint(s["discarded.full"]) + toint(s["discarded.nf"]))
    by HostName, Queue = tostring(s.name)
| where Full > 0 or Discarded > 0 or MaxSize > 20000 or (Queue endswith "[DA]" and MaxSize > 0)

rsyslog output failing Sev 2

An output, such as the Palo Alto files or the AMA port, reported failures or suspensions, or rsyslog logged a warning or error.

kql
let counters = Syslog
    | where TimeGenerated > ago(15m) and ProcessName == "rsyslogd-pstats"
    | extend s = parse_json(SyslogMessage)
    | where tostring(s.origin) == "core.action"
    | summarize Failed = sum(tolong(s.failed)), Suspended = sum(tolong(s.suspended)) by HostName, Output = tostring(s.name)
    | where Failed > 0 or Suspended > 0
    | project HostName, Detail = strcat(Output, ": failed ", Failed, ", suspended ", Suspended);
let messages = Syslog
    | where TimeGenerated > ago(15m) and ProcessName == "rsyslogd"
    | where SeverityLevel in ("warning", "err", "crit", "alert", "emerg")
    | project HostName, Detail = SyslogMessage;
union counters, messages

No input Sev 1

The port 514 listeners received nothing for 15 minutes.

kql
Syslog
| where TimeGenerated > ago(15m) and ProcessName == "rsyslogd-pstats"
| extend s = parse_json(SyslogMessage)
| where tostring(s.origin) in ("imudp", "imtcp") and isnotnull(s.submitted)
| summarize Received = sum(tolong(s.submitted)) by HostName
| where Received == 0

Source silent Sev 3

A regular sender, meaning one active in at least 20 of the last 24 hours, has been silent for 60 minutes. It only covers tables on the analytics tier.

kql
let silentAfter = 60m;
let lookback = 1d;
union isfuzzy=true
    (Syslog | where TimeGenerated > ago(lookback)
        | summarize Last = max(TimeGenerated), ActiveHours = dcount(bin(TimeGenerated, 1h)) by Source = strcat("Syslog / ", HostName, " / ", Facility)),
    (CommonSecurityLog | where TimeGenerated > ago(lookback)
        | summarize Last = max(TimeGenerated), ActiveHours = dcount(bin(TimeGenerated, 1h)) by Source = strcat("CEF / ", DeviceVendor, " / ", Computer)),
    (PaloAltoThreat_CL | where TimeGenerated > ago(lookback)
        | summarize Last = max(TimeGenerated), ActiveHours = dcount(bin(TimeGenerated, 1h)) by Source = strcat("PA threat / ", Computer)),
    (PaloAltoUrlFiltering_CL | where TimeGenerated > ago(lookback)
        | summarize Last = max(TimeGenerated), ActiveHours = dcount(bin(TimeGenerated, 1h)) by Source = strcat("PA url / ", Computer)),
    (PaloAltoTraffic_CL | where TimeGenerated > ago(lookback)
        | summarize Last = max(TimeGenerated), ActiveHours = dcount(bin(TimeGenerated, 1h)) by Source = strcat("PA traffic / ", Computer))
| where ActiveHours >= 20 and Last < ago(silentAfter)

Volume drop Sev 3

A table ingested under a third of what it did in the same 3 hours yesterday. The third leaves room for quieter weekends.

kql
let window = 3h;
Usage
| where TimeGenerated > ago(window) or TimeGenerated between (ago(1d + window) .. ago(1d))
| where DataType in ("Syslog", "CommonSecurityLog", "PaloAltoThreat_CL", "PaloAltoUrlFiltering_CL", "PaloAltoTraffic_CL")
| summarize NowMB = sumif(Quantity, TimeGenerated > ago(window)),
            YesterdayMB = sumif(Quantity, TimeGenerated <= ago(1d))
    by DataType
| where YesterdayMB > 0 and NowMB < YesterdayMB / 3

DCR errors Sev 2

This is a metric alert rather than a query: on each DCR, alert when Logs Rows Dropped per Min or Logs Transformation Errors per Min is above 0 over 5 minutes. The rows themselves and the reason are in DCRLogErrors.
