Option A — adapt the parser (3 edits)

Insert a normalization block right after the table reference, then replace the three references downstream:

kusto
TaniumThreatResponse_CL
| extend
    _MatchDetails = coalesce(tostring(column_ifexists("Match_Details_json","")),
                             tostring(column_ifexists("Match_Details_s",""))),
    _Link         = coalesce(tostring(column_ifexists("Link_s","")),
                             tostring(column_ifexists("Link",""))),
    _EID          = coalesce(column_ifexists("EID_d", real(null)),
                             toreal(column_ifexists("EID","")))
| where isnotempty(Alert_Id_g)
| where intel_type_filter == "" or Intel_Type_s == intel_type_filter
| extend md = todynamic(_MatchDetails)
...

Then in the summarize (your line ~174-175): Link_s = take_any(_Link), EID_d = take_any(_EID).

column_ifexists is what lets one parser span both eras — during the overlap, old rows populate Match_Details_s and new rows populate Match_Details_json. Downstream rule output names stay identical, so no analytics rule changes.

Option B — adapt the DCR instead (parser unchanged)

Edit the deployed DCR's transformKql to emit your legacy names:

Match_Details_s = tostring(j),
Link_s = Link,
EID_d = toreal(EID),

Delete the ~60 Match_Details_* projections while you're in there. Parser works byte-for-byte unchanged, one column set, lower ingestion cost. Cost: you've diverged from the vendor transform, so the Tanium workbook (which presumably reads the exploded columns) won't work.
