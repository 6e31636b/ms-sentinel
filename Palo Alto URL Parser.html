Palo Alto URL Parser

Change plan · Sentinel syslog collectors

Parse the Palo Alto URL filtering logs

The URL filtering DCR sends each log as one raw line. This change makes it extract 24 fields as well: who browsed, what they asked for, what the firewall decided, and how to pivot to the traffic logs. Positions come from Palo Alto's URL Filtering Log Fields reference, and only fields that sit at the same position in PAN-OS 10.1, 10.2 and the current NGFW docs are used. Nothing changes on the collectors.

The fields

ColumnTypePAN-OS field (position)Why
GeneratedTimestringGenerated Time (6)When the firewall logged the request (firewall local time, kept as text like in the traffic table)
DeviceNamestringDevice Name (59)Which firewall logged it
SubtypestringThreat/Content Type (4)Always url here; confirms the rsyslog routing
SourceUserstringSource User (12)Who browsed (needs User-ID)
SourceIPstringSource Address (7)Which client
SourceZonestringSource Zone (16)Which network segment the client sits in
NatSourceIPstringNAT Source IP (9)The public address the site saw; matches external abuse reports
XForwardedForstringX-Forwarded-For (48)The real client when requests come through a proxy
UrlstringURL/Filename (31)The requested URL
UrlHoststringURL/Filename, host part (31)Host name only, for domain indicators and grouping
CategorystringCategory (33)URL category the policy acted on
ActionstringAction (30)allow, alert, block-url, continue, override and so on
SeveritystringSeverity (34)Severity the firewall assigned
RuleNamestringRule Name (11)Security rule that matched
ApplicationstringApplication (14)App-ID, for example web-browsing or ssl
HttpMethodstringHTTP Method (63)GET, POST and so on
UserAgentstringUser Agent (46)Browser or tool that made the request
RefererstringReferer (49)Page that led to the request
ContentTypestringContent Type (41)Type of the response, for example an executable download
DestinationIPstringDestination Address (8)Server address
DestinationPortintDestination Port (25)Web traffic on unusual ports stands out
DestinationZonestringDestination Zone (17)Usually the internet-facing zone
DestinationCountrystringDestination Country (39)Where the server is
SessionIdstringSession ID (22)With DeviceName, joins to PaloAltoTraffic_CL for bytes and duration
  • TimeGenerated, RawData and FilePath stay as they are. Computer becomes the firewall's name, taken from the log file name, the same as in PaloAltoTraffic_CL. Until now it held the collector's name, which stays visible in _ResourceId.
  • UserAgent, Referer and XForwardedFor are only filled when HTTP Header Logging is turned on for them in the URL Filtering profile. For HTTPS they also need decryption. Without it the firewall only sees the host name, so Url holds just the host and the HTTP fields stay empty.
  • URL Category List and XFF Address sit at position 75 and 79 in PAN-OS 10.x but at 77 and 81 in the current docs, so they're left out. Tell me your PAN-OS version and I'll add them at the right positions.
1

Find the DCR and back it up

Open Cloud Shell in Bash mode (in PowerShell mode, type bash first). If Cloud Shell restarts later, run steps 1 and 2's blocks again before continuing.

bash
RG=alp-rg-sentinel-prod-01
WS=alp-law-sentinel-prod-01
# DCRs with "url" in the name: one of them is the URL filtering DCR
az resource list --resource-type Microsoft.Insights/dataCollectionRules --query "[?contains(name, 'url')].name" -o tsv

Set DCR to the URL filtering DCR's name, then back it up and print what it does today:

bash
DCR=alp-dcr-sentinel-prod-01-linux-collector-pan-url   # change to the name printed above
DCR_ID=$(az resource list -n "$DCR" --resource-type Microsoft.Insights/dataCollectionRules --query "[0].id" -o tsv); echo "$DCR_ID"
az rest --method get --url "$DCR_ID?api-version=2023-03-11" > url-dcr-backup.json
# The data flow and its current transformation
jq -r '.properties.dataFlows[] | "\(.streams[0]) -> \(.outputStream)\n  \(.transformKql // "(no transformation)")"' url-dcr-backup.json
# Columns the input stream delivers
jq -r '.properties.streamDeclarations | to_entries[] | "\(.key): \([.value.columns[].name] | join(", "))"' url-dcr-backup.json
TABLE=$(jq -r '[.properties.dataFlows[].outputStream | select(startswith("Custom-"))][0] | sub("^Custom-"; "")' url-dcr-backup.json); echo "$TABLE"

Expect one flow from a Custom-Text-… stream to Custom-<table>, no field extraction, and stream columns that include TimeGenerated, RawData, FilePath, Computer. The last line prints the table name. If any of that looks different, stop and send me the output.

2

Add the columns to the table

The table needs the new columns before the DCR sends them; columns the table doesn't have are dropped. The CLI's --columns replaces the table's whole column list, so this block starts from the current columns and adds the new ones:

bash
az monitor log-analytics workspace table show -g "$RG" --workspace-name "$WS" -n "$TABLE" -o json > url-table-before.json
NEW="GeneratedTime=string DeviceName=string Subtype=string SourceUser=string SourceIP=string SourceZone=string NatSourceIP=string XForwardedFor=string Url=string UrlHost=string Category=string Action=string Severity=string RuleName=string Application=string HttpMethod=string UserAgent=string Referer=string ContentType=string DestinationIP=string DestinationPort=int DestinationZone=string DestinationCountry=string SessionId=string"
COLS=$( { jq -r '.schema.columns[] | "\(.name)=\(.type)"' url-table-before.json; printf '%s\n' $NEW; } | awk -F= '!seen[$1]++' )
# Preview: the table's current columns first, then the 24 new ones
echo "$COLS"

Check the preview: every column the table has today must be at the top. Then apply it:

bash
az monitor log-analytics workspace table update -g "$RG" --workspace-name "$WS" -n "$TABLE" --columns $COLS -o none
# Expect the old columns plus the new ones
az monitor log-analytics workspace table show -g "$RG" --workspace-name "$WS" -n "$TABLE" --query "schema.columns[].name" -o tsv | tr '\n' ' '; echo
3

Test on real rows

Run this in Logs. It feeds the last hour's raw lines through exactly the transformation step 4 deploys. The queries on this page use PaloAltoUrl_CL; if step 1 printed another table name, change it.

kql
// Runs the new transformation on rows already in the table. Nothing is deployed.
let source = PaloAltoUrl_CL
    | where TimeGenerated > ago(1h)
    | take 50
    | project TimeGenerated, RawData, FilePath, Computer;
source
| extend f = extract_all(@'(?:^|,)("[^"]*"|[^,]*)', RawData)
| project TimeGenerated, RawData, FilePath,
    Computer = extract(@'([^/]+)\.log$', 1, FilePath),
    GeneratedTime = tostring(f[6]),
    DeviceName = tostring(f[59]),
    Subtype = tostring(f[4]),
    SourceUser = extract(@'^"?(.*?)"?$', 1, tostring(f[12])),
    SourceIP = tostring(f[7]),
    SourceZone = tostring(f[16]),
    NatSourceIP = tostring(f[9]),
    XForwardedFor = extract(@'^"?(.*?)"?$', 1, tostring(f[48])),
    Url = extract(@'^"?(.*?)"?$', 1, tostring(f[31])),
    UrlHost = extract(@'^"?(?:[A-Za-z][A-Za-z0-9+.-]*://)?([^/:?#"]+)', 1, tostring(f[31])),
    Category = tostring(f[33]),
    Action = tostring(f[30]),
    Severity = tostring(f[34]),
    RuleName = tostring(f[11]),
    Application = tostring(f[14]),
    HttpMethod = tostring(f[63]),
    UserAgent = extract(@'^"?(.*?)"?$', 1, tostring(f[46])),
    Referer = extract(@'^"?(.*?)"?$', 1, tostring(f[49])),
    ContentType = extract(@'^"?(.*?)"?$', 1, tostring(f[41])),
    DestinationIP = tostring(f[8]),
    DestinationPort = toint(f[25]),
    DestinationZone = tostring(f[17]),
    DestinationCountry = extract(@'^"?(.*?)"?$', 1, tostring(f[39])),
    SessionId = tostring(f[22])
| project-away RawData, FilePath

Check a few rows: Url and UrlHost filled, Subtype = url, Action and Category look right, and DeviceName is a firewall. Compare one row against its raw line if anything looks shifted.

4

Deploy the transformation

Save the transformation to a file:

bash
cat > url-transform.kql <<'EOF'
source
| extend f = extract_all(@'(?:^|,)("[^"]*"|[^,]*)', RawData)
| project TimeGenerated, RawData, FilePath,
    Computer = extract(@'([^/]+)\.log$', 1, FilePath),
    GeneratedTime = tostring(f[6]),
    DeviceName = tostring(f[59]),
    Subtype = tostring(f[4]),
    SourceUser = extract(@'^"?(.*?)"?$', 1, tostring(f[12])),
    SourceIP = tostring(f[7]),
    SourceZone = tostring(f[16]),
    NatSourceIP = tostring(f[9]),
    XForwardedFor = extract(@'^"?(.*?)"?$', 1, tostring(f[48])),
    Url = extract(@'^"?(.*?)"?$', 1, tostring(f[31])),
    UrlHost = extract(@'^"?(?:[A-Za-z][A-Za-z0-9+.-]*://)?([^/:?#"]+)', 1, tostring(f[31])),
    Category = tostring(f[33]),
    Action = tostring(f[30]),
    Severity = tostring(f[34]),
    RuleName = tostring(f[11]),
    Application = tostring(f[14]),
    HttpMethod = tostring(f[63]),
    UserAgent = extract(@'^"?(.*?)"?$', 1, tostring(f[46])),
    Referer = extract(@'^"?(.*?)"?$', 1, tostring(f[49])),
    ContentType = extract(@'^"?(.*?)"?$', 1, tostring(f[41])),
    DestinationIP = tostring(f[8]),
    DestinationPort = toint(f[25]),
    DestinationZone = tostring(f[17]),
    DestinationCountry = extract(@'^"?(.*?)"?$', 1, tostring(f[39])),
    SessionId = tostring(f[22])
EOF

Put it into the DCR copy and preview it. Nothing is deployed yet:

bash
jq --arg out "Custom-$TABLE" --rawfile kql url-transform.kql '
  ([.properties.dataFlows[] | select(.outputStream == $out)] | length) as $n
  | if $n != 1 then error("expected 1 flow to \($out), found \($n)") else . end
  | .properties.dataFlows |= map(if .outputStream == $out then .transformKql = $kql else . end)
' url-dcr-backup.json > url-dcr-new.json
# Preview: the start of the new transformation
jq -r '.properties.dataFlows[] | "== \(.outputStream)\n\(.transformKql)"' url-dcr-new.json | head -8
# Must end with: OK, only dataFlows changed
diff <(jq -S 'del(.properties.dataFlows)' url-dcr-backup.json) <(jq -S 'del(.properties.dataFlows)' url-dcr-new.json) && echo "OK, only dataFlows changed"

Deploy:

bash
# Expect: Succeeded
az rest --method put --url "$DCR_ID?api-version=2023-03-11" --body @url-dcr-new.json --query properties.provisioningState -o tsv

If the command fails, nothing has changed; send me the error. The collectors need nothing. The change usually takes effect within minutes; allow up to an hour.

5

Verify

In Logs, 15 to 30 minutes after deploying:

kql
// Expect Parsed = Rows, Subtypes = ["url"], and your firewalls in Firewalls
PaloAltoUrl_CL
| where TimeGenerated > ago(15m)
| summarize Rows = count(), Parsed = countif(isnotempty(Url)), Subtypes = make_set(Subtype), Firewalls = make_set(DeviceName)
kql
PaloAltoUrl_CL
| where TimeGenerated > ago(15m)
| project TimeGenerated, DeviceName, SourceUser, SourceIP, Action, Category, UrlHost, Url, HttpMethod, UserAgent
| take 20

In the Azure portal, open the DCR and select Metrics: Logs Transform Errors per Min and Logs Rows Dropped per Min should stay at 0. Rows from before the change keep only their raw line.

Roll back

Put the backed-up DCR back. The new columns can stay in the table; they simply stay empty. If Cloud Shell has restarted, set RG, WS, DCR and DCR_ID from step 1 first.

bash
# Expect: Succeeded
az rest --method put --url "$DCR_ID?api-version=2023-03-11" --body @url-dcr-backup.json --query properties.provisioningState -o tsv

Using the fields

Two examples of what the columns are for. Category names are Palo Alto's predefined URL categories.

kql
// Monitoring: requests to high-risk categories, per user and hour
PaloAltoUrl_CL
| where TimeGenerated > ago(1d)
| where Category in ("malware", "phishing", "command-and-control", "grayware", "ransomware")
| summarize Requests = count(), Blocked = countif(Action startswith "block"), Hosts = make_set(UrlHost, 20)
    by SourceUser, SourceIP, DeviceName, Category, bin(TimeGenerated, 1h)
kql
// Investigation: what one client browsed, with bytes from the traffic log
let client = "10.29.5.20";
PaloAltoUrl_CL
| where TimeGenerated > ago(1d) and SourceIP == client
| join kind=leftouter (
    PaloAltoTraffic_CL
    | where TimeGenerated > ago(1d) and SourceIP == client
    | project SessionId, DeviceName, BytesSent, BytesReceived, ElapsedTime
  ) on SessionId, DeviceName
| project TimeGenerated, Action, Category, UrlHost, Url, HttpMethod, Referer, BytesSent, BytesReceived
| order by TimeGenerated asc

Session IDs are per firewall and get reused over time, so join on SessionId and DeviceName within a limited time window.
